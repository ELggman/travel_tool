# 沿路 · 双真机测试用例

- 适用版本：`v3.8-route-labels`（2026-10-27）
- APK：`android/build/yanlu-spike-debug.apk`
- 目标：用两台 Android 手机验证当前已实现功能，不验证未实现功能
- 结论记录：每项填“通过 / 失败 / 未测”，失败附日志/截图

---

## 0. 测试前准备

### 设备

| 角色 | 要求 |
|---|---|
| 手机 A（Host/房主） | Android 8+，建议 4 GB RAM 以上，2 GB 可用空间 |
| 手机 B（Guest/同行） | Android 8+，建议 4 GB RAM 以上，2 GB 可用空间 |

### 安装

```bash
adb install -r android/build/yanlu-spike-debug.apk
```

或直接把 APK 传到手机安装。允许“未知来源”。

### 网络

两条链路都测：

1. **共同 Wi-Fi**：A/B 连同一个路由器，关闭移动数据
2. **房主热点**：A 开热点，B 连 A 的热点，关闭移动数据

### 地图包

测试 LAN 前，先在两台手机各下载至少一个城市包（重庆/武汉/贵阳）：

- 同一 Wi-Fi 下，把包服务器地址设为电脑局域网 IP（例如 `http://192.168.1.10:8090`）
- 或使用已部署的静态包地址
- 热点场景建议先在共同 Wi-Fi 下下载好包，再切热点；否则电脑需要连到热点

## 3. 地图与路线（P0）

### MAP-01 地图交互

**步骤**

1. 打开当天页
2. 缩放、平移
3. 点击站点

**预期**

- 地图可缩放/平移
- 站点编号/路线可见
- 点击站点能打开编辑面板

### ROUTE-01 路线与时间

**步骤**

1. 当天安排 3–4 个地点
2. 观察时间轴和地图

**预期**

- 每段有步行/打车标签
- 打车显示“打车 · 估算”
- 算路失败时显示“粗略”
- 总里程与分段里程一致

### ROUTE-02 拖动重排

**步骤**

1. 拖动一个站点到新位置
2. 等待重算

**预期**

- 顺序变化
- 路线和时间自动更新
- 页面没有卡死

### ROUTE-03 切换步行/打车

**步骤**

1. 点击段的交通方式按钮
2. 切换步行 ↔ 打车

**预期**

- 标签切换
- 路线/时间重新计算
- 结果持久化

## 4. 行程编辑（P0）

### EDIT-01 新增地点

**步骤**

1. 当天页点“添加地点”
2. 搜索一个地点并加入
3. 或地图点选一个位置

**预期**

- 地点出现在时间轴
- 地图出现新站点
- 路线更新

### EDIT-02 编辑地点

**步骤**

1. 打开一个站点
2. 修改类别、停留时间、备注
3. 保存

**预期**

- 时间轴立即更新
- 重新打开仍保留

### EDIT-03 删除地点

**步骤**

1. 打开一个站点
2. 删除
3. 确认

**预期**

- 站点消失
- 路线更新
- 刷新/重开 App 后仍不存在

### DAY-01 多日与每日城市

**步骤**

1. 新增一天
2. 给该天切换城市
3. 切换回第 1 天

**预期**

- 每天独立路线
- 城市切换只影响当天
- 总览天数/总里程更新

### TRANS-01 交通班次

**步骤**

1. 打开一个站点
2. 设为交通班次
3. 填写班次、车站、发车/到达、提前到站

**预期**

- 站点显示交通摘要
- 到站时间 = 发车 - 提前
- 下一段从到达时间继续

### STAY-01 住宿

**步骤**

1. 添加住宿
2. 填写名称、入住/退房、晚数、地址、订单号
3. 保存
4. 移除住宿

**预期**

- 卡片显示完整信息
- 刷新后保留
- 移除后不再显示

### TIME-01 每日时间约束

**步骤**

1. 设置最早出发 10:00
2. 设置最晚结束 12:00
3. 安排超过 12:00 的行程

**预期**

- 时间轴从 10:00 开始
- 显示“超出最晚时间 …”

## 5. 局域网：房主与加入（P0）

### LAN-01 房主开房

**步骤**

1. 手机 A 打开“同行”
2. 设置昵称
3. 点“开启房间（房主）”
4. 记录页面显示的 IP、房间码

**预期**

- 显示地址（例如 `192.168.43.1:8766`）
- 显示 26 位房间码
- 版本 v1
- 在线 1 人
- 不要求账号/云端

### LAN-02 Guest 加入

**步骤**

1. 手机 B 连同一 Wi-Fi 或 A 的热点
2. 打开“同行”
3. 设置昵称
4. 输入 A 的 IP 和 26 位房间码
5. 点“加入并拉取”

**预期**

- 加入成功
- 两端都显示在线 2 人
- 显示两个昵称
- 显示彼此当前天/地点 presence

**结果：** ☐ 通过 ☐ 失败 ☐ 未测

### LAN-03 错误 token

**步骤**

1. 输入错误房间码
2. 尝试加入

**预期**

- 加入失败
- 不泄露行程
- 连续错误后可能提示 429；稍后/重启房主可恢复

## 6. 同步与冲突（P0）

### SYNC-01 双向自动同步

**步骤**

1. A 改当天标题
2. 等待 2–4 秒
3. 观察 B
4. B 改一个站点类别
5. 等待 2–4 秒
6. 观察 A

**预期**

- 两端都自动更新
- 不需要手动发布/拉取
- 版本递增

**通过标准：** 单次修改在 5 秒内出现在另一端。

### SYNC-02 同字段冲突

**步骤**

1. A/B 同时改同一个字段（例如同一天标题）
2. 两边都等自动同步

**预期**

- 只有一个分支写入成功
- 另一端显示冲突卡片
- 冲突路径可读（例如 `trip.days[...].title`）
- 点“采用远端”后两端一致
- 不静默覆盖

### SYNC-03 删除不复活

**步骤**

1. A 删除一个站点
2. 等待同步
3. B 重连/刷新
4. 再查看该站点

**预期**

- 两端都不再有该站点
- 旧连接/重连后不复活

### SYNC-04 房主关闭

**步骤**

1. A 点“关闭房间”
2. B 等待 6–15 秒

**预期**

- B 显示“房主已离开或房间已关闭，本机数据仍保留”
- B 的行程仍在
- 不自动清空

### SYNC-05 锁屏/后台

**步骤**

1. B 锁屏 30 秒
2. A 改标题
3. B 解锁并回到 App

**预期**

- 不误报房主离开
- 回到前台后自动同步
- 不丢本地数据

### SYNC-06 断网恢复

**步骤**

1. B 开飞行模式
2. B 改标题/类别
3. 保持 60 秒
4. 关闭飞行模式

**预期**

- B 可继续本地编辑
- 恢复后自动补齐
- A 收到修改
- 不要求手动发布

### NET-01 房主热点

**步骤**

1. A 开手机热点
2. B 连 A 热点，双方关闭移动数据
3. 重复 LAN-01/02、SYNC-01

**预期**

- 与共同 Wi-Fi 行为一致
- 能加入、同步
- 不断言“公网/互联网可用”

**预期**

## 10. 明确不在当前范围

以下失败不算缺陷，除非产品范围改变：

- 公网/跨网络同步
- 账号、云端备份、远程踢人
- 操作日志回放 / 增量 delta / CRDT
- 照片/票据同步
- 公交/地铁
- iOS
- 应用商店上架
- 公共 Wi-Fi 安全承诺
- 加密传输（当前明文 HTTP；仅可信局域网）
