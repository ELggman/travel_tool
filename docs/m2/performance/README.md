# M2.3c · 地图启动性能

- 日期：2026-10-24
- 状态：Web + Android 35 arm64 模拟器验证通过

## 问题

主城全区包有 6407 个瓦片。旧实现每次启动都会：

1. 从 CacheStorage 取出全部瓦片
2. 为每个瓦片创建 Blob URL
3. 才开始创建 MapLibre 地图

在真机上表现为每次进入 App 都要等 2–3 秒，地图才出现。

## 修复

启动时不再全量物化：

- 先加载 **z0–10** 全部瓦片（约 20 张）
- 加当前行程 bbox 覆盖的 **z11–15** 瓦片（几十张）
- 首帧地图出来后再后台加载剩余高缩放瓦片
- 精细层是核心区 z16，首帧后再后台加载
- 地图加载完把当前视图截图缓存到 `yanlu-preview-v2`；下次进入先显示上次地图，再无缝换成真实地图
- App 不再阻塞等待缓存校验：先用 localStorage 的上次城市状态渲染，校验放到后台
- Android WebView / Activity 启动底色改为纸张色，避免原生白屏

MapView 仍然使用 `transformRequest → Blob URL`，因为 Android WebView 对 MapLibre 自定义协议不兼容；但只物化当前需要的瓦片。

## 结果

- 首屏不再等待 6407 张瓦片全部读完
- 启动阶段不再停在“正在读取本机地图包…”白屏/空白页
- 首帧前只物化当前行程需要的少量瓦片
- 第二次进入时显示上次地图预览，减少白屏观感
- 地图出现后，后台继续补齐高缩放瓦片
- Web 和 Android 模拟器都能正常显示主城全区底图、6.9 km 路线
- 精细层仍是可选 z16 叠加层，按需加载

## 仍然要注意

- 第一次打开某个区域、或快速拖动到未预载区域时，后台补瓦片可能短暂出现空白
- 后续可以把预载范围从“行程 bbox”扩展为“当前视口 bbox + 拖动方向预测”
- 原生 Android 本地 HTTP 服务直接读 pack 文件，会比 CacheStorage + Blob 更快，这是 M3 的方向
- 精细层只在核心区 z16 生效
