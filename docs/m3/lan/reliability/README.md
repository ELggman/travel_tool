# M3.2a · 局域网通信可靠性

- 日期：2026-10-27
- 状态：API + Android 模拟器验证通过；两台 Android 真机待验证
- 目标：先保证“不静默覆盖、可离开、请求不堆积”，再做字段级合并

## 本轮修复

### 1. 冲突检测

- 本机有未同步修改（`trip !== lanJsonRef`）时收到远端新版本
- 不再自动覆盖
- 显示冲突卡片：
  - 采用远端
  - 保留本机并推送
- 冲突期间暂停自动发布，直到用户选择

### 2. 显式离开

- 新增 `POST /leave?room=&id=`
- 成员立即从在线列表移除
- 浏览器 Guest 和 Android 都调用
- 服务端仍有 12 秒 TTL 兜底

### 3. 请求超时

- `/info`、`/snapshot`、`/hello`、`/members`、`/leave` 统一 3.5 秒超时
- 轮询有 in-flight 防重入
- 失败不会无限堆积

### 4. 房间安全

- `/info` 现在必须带正确房间码
- 未带返回 403，不再泄露房间码
- `/snapshot`、`/members`、`/leave` 均要求房间码

### 5. 服务端资源

- 新房间清空 snapshot/version/members
- POST 快照 2 MB 上限，超限 413
- 请求体批量读取
- 成员过期用 `removeIf`

## 验证

```text
GET /info                  -> 403
GET /info?room=152790      -> 200
POST /hello                -> 在线 2 人
GET /members               -> 房主 / 测试同行
POST /leave                -> 房主（测试同行已移除）
GET /info（无房间码）       -> 403
```

此前已验证：

- 房主自动发布 v1
- Guest 加入自动拉取
- Guest 改标题，房主自动收到
- 房主改标题，Guest 自动更新
- 在线人数从 1 变 2

## 限制

- 冲突仍然是**整份 Trip 二选一**，不是字段级自动合并
- 双方几乎同时自动推送时，仍可能在后到的请求上覆盖；冲突 UI 只能覆盖“检测到远端版本”的情况
- 没有操作日志、tombstone、字段版本
- 没有传输加密
- 房间码仍是 6 位，无速率限制
- 两台 Android 真机未实测
