# 三城地图与离线路由 · 验证计划

- 状态：第一轮已执行（2026-10-22），结果见 [docs/spikes/city-map-report.md](spikes/city-map-report.md)
- 关联规划：[docs/PLAN.md](PLAN.md)
- 目的：在正式重构 App 前，用 **重庆 / 武汉 / 贵阳** 验证“开源地图栈 + 离线城市包 + 本地步行/打车路由”是否足以支撑第一版。
- 原则：这是技术验证，不是最终产品；结果可能迫使我们改地图栈，先不要大规模写业务 UI。

---

## 0. 第一轮结果（2026-10-22）

- 三城 30 条样本全部能算出路线；28/30 与 OSRM 基线距离误差 ≤10%，29/30 ≤20%。
- 单城 PMTiles 3.65–7.25 MB，两张路网图 6.47–13.96 MB。
- 浏览器内 A* 4–6 ms（桌面），断外网仍能加载与重算。
- Android 壳已在 Android 35 arm64 模拟器验证：三城切换、离线加载、浏览器 A*；物理真机待连接。
- 条件通过，继续开源栈 A；异常路线与出租车时长仍需修正。
- 详细数据、截图与限制见 [city-map-report.md](spikes/city-map-report.md)。

## 1. 验证范围

- 城市：重庆、武汉、贵阳。
- 第一版只验证 **步行 + 打车/驾车**，不做公交、地铁、轮渡。
- 先做城市核心区/常用旅行区域，不承诺整个直辖市/地级市行政区。
  - 重庆尤其需要注意：行政区范围很大，第一版只覆盖主城核心（渝中、江北、南岸等）即可，后续按需扩展。
- 在线底图与离线包都基于 OSM / WGS-84；路线统一使用本地路网图，不引入第二套坐标或路网。在线底图可由 OpenFreeMap 或自托管瓦片提供，版本可与离线包不同，但 UI 要标明当前是哪种模式。

## 2. 数据与工具

| 环节 | 工具/数据 | 备注 |
|---|---|---|
| OSM 原始数据 | Geofabrik China PBF / BBBike 城市提取 | 先确认下载可用性与体积 |
| 裁剪 | `osmium extract` + 城市 bbox/多边形 | 只保留目标区域 |
| 底图瓦片 | Planetiler → PMTiles | 包含道路、建筑、绿地、水系、中文标签所需数据 |
| 字体/图标 | Protomaps basemaps-assets | 离线中文标签必须本地化 glyphs/sprites |
| 路网图 | 从裁剪后的 OSM 生成步行/汽车图 | 先用 GraphHopper/OSRM 生成基线，再试 TS A* 图格式 |
| 客户端渲染 | MapLibre GL JS + PMTiles | 与后续 App 同栈 |
| 路由基线 | OSRM / GraphHopper / Valhalla | 只用于对比质量，不一定进 App |
| 移动端验证 | Android 真机 / 桌面性能模拟 | 后续再进 Capacitor |

> 不要把 PBF、PMTiles、路网图提交到 Git；只提交脚本、bbox 配置、manifest 与验证报告。

## 3. 三城的验证重点

### 重庆

- 地形：山地、立体交通、密集隧道/桥梁/立交，步行高差大。
- 重点看：
  - 渝中半岛的步行连接（解放碑—洪崖洞—来福士—十八梯）；
  - 李子坝、鹅岭二厂一带的坡道/楼梯；
  - 跨江（桥梁/隧道）打车路线；
  - OSM 是否把主要步行道、楼梯、扶梯连接起来。
- 风险：距离/时间不考虑坡度会偏乐观；地图上看起来很近，实际高差很大。第一版明确“时间估算”，不承诺爬坡难度。

### 武汉

- 地形：两江三镇、桥梁/隧道、东湖与大量城市快速路。
- 重点看：
  - 跨江步行是否只走可步行桥梁；
  - 打车跨江走桥还是隧道；
  - 黄鹤楼—户部巷—江汉路的短途步行；
  - 东湖绿道、武汉大学周边的步行网络。
- 风险：桥隧选择、单行、快速路出入口；跨江距离长，步行路线可能不合理，需要产品提示。

### 贵阳

- 地形：山地、隧道、立交、老城与新区高差。
- 重点看：
  - 甲秀楼—喷水池—黔灵山公园的步行/打车；
  - 花果园—观山湖的隧道/快速路；
  - 青岩古镇等外围目的地的长距离打车；
  - OSM 覆盖是否明显弱于前两城。
- 风险：数据稀疏、POI 少、隧道/立交导致路线几何不直观；必要时接受地图点选 + 在线搜索。

## 4. 每城测试用例

每城至少 10 条路线，覆盖短途步行、坡道/楼梯、跨江/跨区、隧道/立交、长距离打车。

建议样本（需实际 geocode 校准）：

| 城市 | 步行 | 打车 |
|---|---|---|
| 重庆 | 解放碑 → 洪崖洞；李子坝 → 鹅岭二厂；十八梯 → 较场口 | 解放碑 → 南滨路；观音桥 → 解放碑；磁器口 → 李子坝 |
| 武汉 | 黄鹤楼 → 户部巷；江汉路 → 武汉关；东湖绿道短段 | 武昌 → 汉口（桥/隧道）；武汉大学 → 光谷；汉口站 → 江汉路 |
| 贵阳 | 甲秀楼 → 喷水池；黔灵山公园入口环线；老城短途 | 喷水池 → 花果园；花果园 → 观山湖；市区 → 青岩古镇 |

测试项：

- 起点/终点是否正确吸附到路网；
- 路线是否沿真实道路，是否穿建筑/江面/封闭小区；
- 步行是否错误走上高架/机动车道；
- 打车是否错误走步行道/逆行/封闭路；
- 距离/时间是否与基线引擎差异过大；
- 地图上是否有断头路、缺失桥梁/隧道。

## 5. 指标

### 数据

- 主要道路/桥梁/隧道是否完整；
- 步行道/楼梯/人行天桥覆盖；
- POI 数量与名称质量（餐饮、景点、酒店、车站）；
- 离线包大小、构建时间。

### 路由

- 每城 10 条样本的“人工可接受率”（目标 ≥ 8/10）；
- TS A* 与 OSRM/GraphHopper 基线的距离差异（记录，不强行要求完全一致）；
- 1–5 km 路线计算耗时（目标 < 300 ms，Web Worker）；
- 路网图加载时间与内存；
- 起终点吸附误差。

### 离线

- 飞行模式下地图可打开、可缩放；
- 断网后拖动重排，仍能用本地路网重算步行/打车；
- 超出离线包 bbox 时有明确提示；
- 本地包删除/更新后行为正确。

### 包体积目标

- 第一版单城核心包目标 **≤ 200 MB**（底图 + 路网 + POI + 字体）；超出则降 zoom、裁剪 bbox 或拆子区域。
- 这是目标，不是承诺；以实测为准。

## 7. 验收门槛

- 三城至少各 8/10 样本路线视觉合理；
- 主要桥梁/隧道可用，步行不会大面积穿江/穿楼；
- 离线包能在 Android WebView 中加载；
- 无网络时能重算至少 5 条样本路线；
- 单城核心包 ≤ 200 MB（目标）；
- 形成明确的“继续 A / 改用 B”的结论。

如果不达标：

- 先评估国内 SDK 的离线地图与离线路线能力；
- 或改用 GraphHopper（Android）+ Valhalla（iOS/跨端）；
- 或缩小第一版城市/区域范围。

---

## 8. 风险

- OSM 在中国的 POI/地址覆盖不足，离线搜索可能弱；地图点选必须作为兜底。
- 重庆/贵阳的立体地形会让“距离”和“实际步行体验”差异很大，UI 不要过度承诺。
- 武汉跨江步行可能非常长，产品应主动建议打车。
- 静态 CDN 分发城市包需要 HTTPS、CORS、Range 请求与哈希校验；国内自定义 CDN 域名可能涉及备案。
- 地图数据许可/合规仍需保留版权标注；朋友内部使用不等于可以忽略数据许可。
